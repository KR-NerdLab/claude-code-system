# Git Commit Convention

## 메시지 형식

```
<type>[(<scope>)]: <subject>

[<body>]

[<footer>]
```

- **type**: 필수. 변경의 종류
- **scope**: 선택. 변경 영역 (단일 모듈이면 넣고, 여러 모듈이면 생략)
- **subject**: 필수. 한글, 명령형, 72자 이내 (예: "추가", "수정", "제거")
- **body**: 선택. 변경 배경과 이유 (feat/fix에는 작성 권장)
- **footer**: 선택. 이슈 참조 (예: `Refs: ISSUE-123`)

## Type

| type | 의미 | 사용 시점 |
|------|------|----------|
| `feat` | 새 기능 | 새 API, 새 화면, 새 도메인 로직 |
| `fix` | 버그 수정 | 동작 오류 수정 |
| `refactor` | 구조 개선 | 동작 변경 없이 코드 정리 |
| `chore` | 빌드/설정 | Docker, 의존성, CI |
| `docs` | 문서 | README, 프로젝트 문서 |
| `test` | 테스트 | 테스트 추가/수정 |
| `style` | 포맷/린트 | 린터/포맷터 적용 |
| `perf` | 성능 개선 | 쿼리 최적화, 캐싱 |

## Scope (선택)

변경 영역이 명확한 경우 프로젝트의 모듈/컴포넌트명 사용. 여러 영역에 걸친 변경이면 생략한다.

## 커밋 단위

- 하나의 논리적 변경 = 하나의 커밋
- 리팩터링과 기능 변경을 섞지 않는다
- 포맷/린트 적용은 별도 커밋
- 사용자가 명시적으로 요청할 때만 커밋한다

## 예시

```
feat(auth): 소셜 로그인 OAuth2 플로우 구현

- OAuth2 토큰 검증 로직 추가
- 기존 로그인과 동일한 인증 파이프라인 사용
- 소셜 계정 연동 시 기존 회원 매칭 처리

Refs: ISSUE-42
```

```
fix(api): 필수 파라미터 누락 시 500 에러 수정

요청 body에 필수 필드가 없을 때 서버 에러 발생.
유효성 검사를 추가하여 400 에러로 반환하도록 변경.
```

```
chore: Docker 빌드 캐시 최적화
```
