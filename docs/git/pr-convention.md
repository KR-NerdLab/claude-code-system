# Git PR Convention

main 브랜치 대상 Pull Request 작성 규칙.

## PR 제목

```
<type>(<scope>): <subject>
```

- 커밋 컨벤션과 동일한 형식
- 70자 이내

## PR 본문 템플릿

```markdown
## 요약

이 PR이 해결하는 문제와 변경 이유를 1-3줄로 설명.

## 변경 내용

- 주요 변경사항 bullet point
- 새로 추가된 API나 변경된 동작
- 삭제된 기능이 있다면 명시

## 테스트

- [ ] 테스트 항목 1
- [ ] 테스트 항목 2
- [ ] 테스트 항목 3
```

## 예시

### 제목
```
feat(auth): 소셜 로그인 지원 추가
```

### 본문
```markdown
## 요약

소셜 로그인을 통한 회원가입/로그인 기능 추가.
기존 인증 파이프라인을 재사용하여 일관성 유지.

## 변경 내용

- POST /api/v1/auth/social 엔드포인트 추가
- OAuth2 토큰 검증 로직 구현
- 기존 회원 소셜 계정 연동 처리
- 단위 테스트 5건 추가

## 테스트

- [ ] 신규 회원 소셜 로그인 → 회원가입 완료
- [ ] 기존 회원 소셜 로그인 → 계정 연동
- [ ] 만료된 토큰 → 401 에러 반환
- [ ] 이미 연동된 계정 → 정상 로그인
```

## 작성 기준

- 제목만 보고 어떤 변경인지 파악 가능해야 한다
- 요약에는 "왜" 이 변경이 필요한지 작성한다
- 변경 내용에는 "무엇이" 바뀌었는지 구체적으로 작성한다
- 테스트 항목은 리뷰어(미래의 나)가 확인할 수 있는 체크리스트로 작성한다
